# 来回 · 把你和 Agent 做成一件事的过程分享出来

**以后我们分享教程，会不会直接分享一段和 Agent 的交互记录？**

你想做一个网站，剪一段视频，准备一场考试。你和 Agent 来回讨论、试错，终于把事情弄明白了。这段记录，可能正好能帮到另一个卡在同样地方的人。

来回是一个围绕这些经历展开的社区构想。目前做成了一个可以点击、输入、体验完整流程的网页 Demo，想先听听大家觉得有没有用。

## 为什么做这个

和 Agent 的对话很私人，也可能很有价值。里面不只有模型的回答，还有用户提出的问题、经验、判断，以及反复纠正模型的过程。

与其担心这些内容在自己不知情时被拿去使用，我们想探索另一种方式：**由用户决定哪些内容可以公开、允许别人怎么使用，并让愿意分享的人有机会得到关注和回报。** 公开给别人阅读，不应自动等于同意训练、转售或商业授权。这些是产品想坚持的原则，Demo 还没有实现授权和结算系统。

另一个出发点是：随着 vibe coding 和通过对话完成创作的方式越来越常见，一部分教程可能会变成真实的交互记录。分享者不必重新截十几张图解释一遍；读者可以看他怎么做，也可以把记录交给自己的 Agent，结合自己的情况继续尝试。它是一份参考，不能保证换个环境就一定有效。

## 在这里能做什么

- **分享经历。** 发一段解决问题、学习、生活感悟或创作的对话，打上标签，也可以写两句自己的复盘。没做成的尝试同样可以分享。
- **看别人怎么想。** 看一个人怎么提问、追问、判断回答是否靠谱，或者怎么从完全不会到逐渐学会。
- **把经验带走。** 查看对话、下载 Markdown、准备给自己 Agent 的参考材料；Skill 文件和使用说明也可以放在一起。
- **先来求助。** 征集改简历、备考或某个具体问题的对话记录，让有经验的人接着回答。
- **找人一起做。** 发一段旋律、一个游戏点子、草图或小说开头，让有兴趣的人用自己的 Agent 接着试。
- **自己设计互动。** 出题、设计案件、比较解题思路。破案和海龟汤都只是例子，玩法不必由平台提前规定。

## 三分钟体验路线

1. 在「发现」打开剪视频的帖子，切到完整对话，看看提问和修改过程。
2. 点「带给我的 AI」，把示例需求改成自己的场景，查看参考材料。
3. 点「分享一个经历」，粘贴 [示例对话](examples/一次剪辑尝试.md)，填写标签，检查并编辑预览后发布。
4. 进入「一起做」，看求助、共创和挑战；在案件中输入一个问题，再选择把过程带入分享草稿。
5. 搜索「简历」，打开 Skill 示例，查看文件内容和使用说明。

这里的发布和评论只改变当前浏览器页面，不会发给真实用户。

## 本地运行

不需要 API Key，不需要 npm 安装，也没有构建步骤。需要 Python 3 和现代浏览器。

```bash
git clone https://github.com/shimarinshi/laihui.git
cd laihui
python3 -m http.server 4173 --bind 127.0.0.1 --directory demo
```

打开 <http://127.0.0.1:4173>，按 `Ctrl+C` 停止服务。也可以用其他静态服务器托管 `demo/` 目录。

## 文件结构

```text
demo/
  index.html       页面结构
  app.js           内容样例、浏览、发布、评论与共创交互
  extensions.js    Skill 与应用内对话演示
  styles.css       基础样式
  theme.css        黄白黑主题及组件样式
  assets/          本地演示封面
docs/              产品想法、功能说明、演示讲稿与验证记录
examples/          可导入 Demo 的虚构对话样例
CONTRIBUTING.md     反馈与参与方式
```

源码就是 `demo/` 内的原生 HTML、CSS、JavaScript，封面文件随仓库提供。没有框架依赖、后台或数据库。所有模型回复均为预设示例。项目没有加入统计追踪脚本；访问线上托管服务仍会产生托管方的常规访问记录。

## 接下来想试什么

先验证大家是否愿意分享、是否能找到有用的经历，以及能否把别人的经验用到自己的问题上。之后再考虑持久化、账号、对话导入、模型接入和更完善的隐私检查。

付费内容、授权和作者回报也是探索方向，**目前没有收益承诺或结算功能**。更具体的想法见 [产品说明](docs/产品想法.md)。
